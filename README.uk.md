# FSLTool — менеджер профілів FSLogix

[English](README.md) | **Українська**

Нативна утиліта для Windows (WPF, .NET 10) для файлового сервера, на якому лежать контейнери FSLogix (`Profile_*.vhdx`, `ODFC_*.vhdx`).

## Можливості

| | |
|---|---|
| **Інтерфейс** | Дві вкладки у верхньому рядку: «Контейнери» (картки, таблиця, деталі) і «Налаштування» (шляхи, пороги, правила очищення, тема й мова). Поруч — кнопка «Журнал» (журнал операцій над рядком стану; на кнопці — кількість нових попереджень і помилок), мова, перемикач теми й довідка. Картки, кнопки й поля заокруглені, дії з контейнером зібрано в окрему темну картку: основні видно одразу, рідші — під «Ще дії». Шрифт Manrope вбудовано в exe. |
| **Тема** | Світла й темна. Типово — як у Windows (режим програм у параметрах Windows, змінюється разом із ним); кнопка теми у верхньому рядку або вибір «Як у Windows / Світла / Темна» в налаштуваннях перемикають її одразу, без перезапуску, в усіх відкритих вікнах, включно з кольором заголовка вікна (Windows 11). Вибір запам'ятовується для поточного користувача Windows (`HKCU\Software\FSLTool\Theme`). |
| **Шляхи** | Додаються на сторінці «Налаштування» через діалог або вводяться вручну (UNC теж). Зберігаються в `%ProgramData%\FSLTool\settings.json`, після перезапуску сканування стартує саме. Для кожного шляху видно вільне місце на сховищі (смуга з тими самими порогами, що й для контейнерів) і скільки займають знайдені контейнери; смуги всіх сховищ показано й поруч із заголовком вкладки «Контейнери». |
| **Візуалізація** | Картки (усього / переповнені / у сесії / сироти / вимкнені в AD / неактивні / варто стиснути), гістограма заповнення, топ найбільших, кольорові смуги заповнення в таблиці, фільтри та пошук. Рядки таблиці дворівневі: тип контейнера показано під іменем файлу, максимальний розмір під розміром, позначки під датою зміни, прогрес операції в колонці «Стан». Колонку прапорців «✓» теж можна сортувати: позначені збираються вгорі або внизу. Панель деталей показує заповнення кільцем, історію розміру й (за кнопкою «Усі відомості») решту даних контейнера. |
| **Власний фільтр** | Кнопка «Фільтр» поруч із пошуком (Ctrl+Shift+F) відкриває конструктор: умови за ~50 полями контейнера (текст, розмір, число, дата, так/ні, вибір), оператори для тексту (містить, дорівнює, маска, регулярний вираз, порожнє…), чисел і розмірів (≥, <, від … до, невідомо), дат (давніше ніж N дн., до / після / між датами). Умови об'єднуються в групи «усі (І)» / «будь-яка (АБО)» з інверсією «НЕ», групи можна вкладати без обмеження глибини, кожну умову чи групу можна тимчасово вимкнути. Таблиця оновлюється під час редагування, над нею показано фільтр словами. Фільтри можна зберігати під назвою в `%ProgramData%\FSLTool\filters.json` (спільні для всіх адміністраторів) і застосовувати в режимі без вікна параметром `--where "Назва"`. Умова з неправильним значенням підсвічується й не враховується. |
| **Заповнення** | Без підключення диска: розмір файлу ÷ максимальний розмір із заголовка VHD/VHDX (позначено `*`). Після «Аналізувати» береться точне значення з NTFS-тому всередині. |
| **Підмонтовані** | Відкриті SMB-файли сервера (`MSFT_SmbOpenFile`, запасний варіант — `NetFileEnum`): видно, з якого RDS-хоста і під яким користувачем. Диски, підключені на цьому сервері, визначаються одним викликом `GetAllAttachedVirtualDiskPhysicalPaths`. Під час сканування файли контейнерів на цьому сервері не відкриваються: раніше пробне відкриття 711 VHDX тривало до ~3 хв через антивірус і SMB-оренди RDS-хостів. Блокування іншим процесом перевіряється перед кожною дією, для того файлу, з яким вона працює. Для шляхів на іншому сервері пробне відкриття під час сканування лишилось. |
| **Сеанс на RDS-хості** | Для контейнера, відкритого хостом сеансів, можна надіслати повідомлення в сеанс користувача (`WTSSendMessage`) або завершити сеанс (`WTSLogoffSession`). Під час виходу FSLogix коректно відключає профіль, тому це безпечніше за «Відмонтувати». Потрібні права адміністратора на хості та доступ до нього через RPC. |
| **Відмонтування** | Примусово закриває SMB-дескриптор (`ForceClose`) або відключає локально підключений диск. Перед цим показується попередження. |
| **Вимірювання** | Швидко, кілька секунд на контейнер: підключає диск **лише для читання** й визначає реальне заповнення, скільки поверне стиснення та стан ФС, без обходу папок. Для позначених виконується до 4 одночасно. Картка «Варто стиснути» показує, скільки вільних контейнерів ще не виміряно. Її фільтр відбирає лише тих, кого варто стиснути, а посилання «Ще не виміряні: N →» у рядку фільтра відкриває решту, щоб їх позначити й виміряти. |
| **Аналіз** | Підключає диск **лише для читання** (до 3 контейнерів одночасно; великі папки обходяться в кілька потоків): реальне заповнення, найбільші папки (AppData розбито до рівня `AppData\Local\Vendor`), скільки звільнить кожне правило, до 20 найбільших файлів (від 100 MB, наприклад `*.ost`, `*.pst`, ISO) з кнопкою 🗑 для видалення файлу з контейнера (ті самі захисти, що й при очищенні: `globalExclude` не видаляється; далі ReTrim і стиснення, якщо увімкнено). Результати зберігаються в `%ProgramData%\FSLTool\analysis-cache.json` і доступні після перезапуску (й іншим адміністраторам), доки розмір файлу контейнера не зміниться. |
| **Очищення** | Підключає диск для запису без літери, видаляє дані за правилами, виконує ReTrim, відключає диск і (якщо увімкнено) стискає VHDX. |
| **Стиснення** | Повне стиснення через `CompactVirtualDisk` (диск підключено лише для читання). Роль Hyper-V не потрібна. Після виміру чи аналізу видно, скільки приблизно поверне стиснення (розмір файлу − зайняте в томі): колонка «Стиснення» та картка «Варто стиснути» з порогом у ГБ у налаштуваннях. |
| **Збільшення розміру** | Збільшує максимальний розмір VHD(X) (`ResizeVirtualDisk`, для VHD `ExpandVirtualDisk`) і розширює розділ усередині до нового кінця (`MSFT_Partition.Resize`). Розмір задається абсолютно (`50`) або приростом (`+10`) у GB. Роль Hyper-V не потрібна. `SizeInMBs` у FSLogix діє лише на нові контейнери, тож так існуючий користувач отримує більше місця. |
| **Файлова система** | Під час аналізу читається позначка NTFS «потрібна перевірка» (dirty bit). У позначках вона показується як «ФС: перевірити». «Перевірити ФС» підключає диск для запису та запускає `MSFT_Volume.Repair` (аналог `chkdsk /f`). |
| **Пакетний режим** | Позначте кілька контейнерів, і дія виконається для кожного: зміни йдуть по черзі, вимірювання та аналіз — паралельно. Зайняті контейнери пропускаються. Перевірка «чи вільний контейнер» перед кожною дією швидка: спершу пробне відкриття файлу та `NetFileEnum` за шляхом. Повний WMI-запит відкритих файлів сервера робиться лише тоді, коли `NetFileEnum` недоступний. |
| **Швидкість сканування** | Після переліку файлів заголовки VHDX, стан підключень і облікові записи з AD читаються одночасно, тож сканування триває стільки, скільки найповільніша з цих фаз. Час кожної фази пишеться в журнал (рядок `час:`). |
| **Історія розміру** | Кожне сканування (і режим без вікна) записує розмір контейнера в `%ProgramData%\FSLTool\history.json`: одна точка на день, зберігається 400 днів. Колонка «Приріст» показує, на скільки виріс файл за 30 днів, і прогноз, коли заповнення досягне порогу «Переповнений». Рахуються лише збільшення: падіння після стиснення не враховуються. Прогноз з'являється, коли історії набирається щонайменше 7 днів. Колонку можна сортувати за швидкістю росту. На панелі деталей є графік розміру. |
| **Облікові записи в AD** | Для облікових записів, які ще існують, LDAP-запитом перевіряється, чи вони вимкнені або прострочені (`userAccountControl`, `accountExpires`), і дата останнього входу (`lastLogonTimestamp`). Картка «Вимкнені в AD» працює як фільтр. |
| **Звіт на email** | Режим без вікна може надіслати HTML-лист у стилі програми з підсумками (стан запуску, результат операції, картки стану контейнерів, сховища) і деталями (результат за кожним контейнером, контейнери, що потребують уваги, попередження журналу), а у вкладенні — вивід запуску та CSV з усіма контейнерами. Див. «Режим без вікна». |
| **Аудит** | Кожна дія пишеться в `%ProgramData%\FSLTool\logs\fsltool-yyyyMMdd.log` із зазначенням імені адміністратора. |
| **Мова інтерфейсу** | Українська та англійська. Типово — мова інтерфейсу Windows; якщо перекладу для неї немає — англійська. Вибір мови на сторінці «Налаштування» або кнопкою мови у верхньому рядку змінює її одразу, без перезапуску (вікно, діалоги, статуси, журнал операцій, довідка) і запам'ятовується для поточного користувача Windows (`HKCU\Software\FSLTool\Language`). Режим без вікна бере ту саму мову або `--lang`. |

## Безпека

- Перед кожною операцією стан контейнера перевіряється ще раз. Контейнер, який хтось використовує, **ніколи** не підключається.
- Підключення тимчасове: якщо утиліта впаде, Windows сама відключить диск, коли закриється дескриптор.
- Junction і symlink-посилання не обходяться, видаляється лише саме посилання. Це важливо для профілів (наприклад, `Application Data`, що вказує сам на себе).
- Шляхи з правил не можуть вийти за межі кореня контейнера (`..` заборонено) і не можуть вказувати на сам корінь.
- `globalExclude` (типово `NTUSER.DAT*`, `UsrClass.dat*`, `desktop.ini`) не видаляється жодним правилом.
- Для обходу обмежувальних ACL у профілях вмикаються `SeBackupPrivilege` і `SeRestorePrivilege`.
- Пароль SMTP для звіту на email не зберігається в settings.json і не передається в командному рядку: програма читає його зі змінної середовища, ім'я якої вказано в налаштуваннях.

## Правила очищення

Файл `%ProgramData%\FSLTool\cleanup-rules.json` створюється під час першого запуску з вбудованого шаблону. Відкрити його можна кнопкою «Редагувати», після змін натисніть «Перечитати».

```json
{
  "globalExclude": [ "desktop.ini", "NTUSER.DAT*" ],
  "rules": [
    {
      "name": "Google Chrome — кеш",
      "enabled": true,
      "containers": [ "Profile" ],          // Profile | ODFC | Any
      "paths": [ "AppData\\Local\\Google\\Chrome\\User Data\\*\\Cache" ],
      "action": "DeleteContents",           // DeleteContents | DeleteFolder | DeleteFiles
      "include": [ "*" ],                   // маски файлів
      "exclude": [ ],                       // ніколи не видаляти
      "olderThanDays": 0                    // лише файли, старші за N днів
    }
  ]
}
```

- Шляхи задаються відносно кореневої папки контейнера (`Profile` або `ODFC` усередині VHDX).
- Префікс `$volume\` означає шлях від кореня тому, наприклад `$volume\$RECYCLE.BIN`.
- У сегментах шляху працюють маски `*` і `?`, а `**` означає будь-яку глибину (працює повільно, використовуйте обережно).
- `DeleteContents` очищає вміст папки, `DeleteFolder` видаляє папку повністю, `DeleteFiles` видаляє лише файли за масками `include` безпосередньо в папці.

Необов'язкове поле `"names": { "en": "..." }` задає назву правила іншими мовами інтерфейсу; без нього показується `name`. У вбудованому шаблоні англійські назви вже є; файл, створений попередньою версією, не змінюється — додайте `names` вручну, якщо потрібно.

Шаблон уже містить правила для Temp, INetCache, WER і дампів, кешу мініатюр, Chrome, Edge, Firefox, Teams classic, нових Teams і кошика. Правило для старих Downloads є, але вимкнене.

## Режим без вікна (Планувальник завдань)

```
FSLTool.exe scan | analyze | compact | clean [параметри]
```

| Команда | Що робить |
|---|---|
| `scan` | Сканування: стан, облікові записи, AD, запис історії розмірів. Щоденний `scan` наповнює історію, навіть коли ніхто не відкриває вікно. |
| `analyze` | Аналіз вільних контейнерів (лише читання), оновлює кеш аналізу. |
| `compact` | Стискає вільні контейнери, які стиснення зменшить щонайменше на `--min-gain` GB. Контейнери без даних аналізу спершу швидко вимірюються: підключення лише для читання, кілька секунд. |
| `clean` | Очищення за правилами, а потім стиснення, якщо воно увімкнене в налаштуваннях (`--no-compact` його вимикає). |

Параметри:
- `--filter all|problem|critical|stale|orphan|disabled|compactable` — які контейнери обробляти;
- `--user "<маска>"` — відбір за користувачем або файлом;
- `--where "<назва>"` — відбір збереженим власним фільтром (кнопка «Фільтр» у вікні, `%ProgramData%\FSLTool\filters.json`), разом із `--filter` і `--user`. Якщо фільтра немає, він порожній або містить умову з помилкою, запуск не починається (код 2), щоб не обробити всі контейнери. Поля «Позначено в таблиці» та «Виконується операція» тут завжди «ні»; на `scan` не впливає;
- `--min-gain <GB>` — мінімальний виграш від стиснення;
- `--max-minutes <N>` — нічне вікно: після N хвилин нові контейнери не починаються;
- `--max-count <N>` — обробити не більше N контейнерів;
- `--dry-run` — лише показати план, нічого не змінюючи;
- `--lang uk|en` — мова виводу в консоль, журналу та листа. Типово — мова, обрана в програмі для цього користувача Windows, інакше мова інтерфейсу Windows, інакше англійська (завдання під SYSTEM зазвичай отримує мову інтерфейсу сервера).

Звіт на email:
- `--mail-to "a@x; b@x"` — одержувачі; без них (і без `mail.to` у settings.json) звіт не надсилається;
- `--mail-on always|problems|errors` — коли надсилати: завжди (типово); якщо є помилки, пропуски, переповнені контейнери чи сховища або межа ≤ 30 дн.; лише коли код виходу не 0;
- `--smtp <сервер[:порт]>` (типово порт 25), `--smtp-ssl` (STARTTLS; неявний TLS на 465 не підтримується), `--mail-from <адреса>` (типово `fsltool@<FQDN комп'ютера>`);
- `--smtp-user <логін>` і `--smtp-password-env <ЗМІННА>` — автентифікація; пароль береться зі змінної середовища (для SYSTEM — системна змінна). Без логіна лист надсилається анонімно;
- `--no-mail` — не надсилати, навіть якщо налаштовано в settings.json.

Типові значення — розділ `mail` у `%ProgramData%\FSLTool\settings.json` (`smtpHost`, `smtpPort`, `ssl`, `from`, `to`, `user`, `passwordEnv`, `when`); у вікні програми їх немає. Якщо `mail.to` заповнено, звіт надсилають усі запуски без вікна. Помилки налаштувань пошти виявляються до початку роботи (код 2).

Лист — HTML у кольорах програми: стан запуску й параметри, картки результату операції (або план для `--dry-run`) і стану контейнерів, сховища, деталі за кожним контейнером (помилки й пропуски першими), контейнери, що потребують уваги, попередження та помилки журналу. Таблиці обмежено 50 рядками. У вкладенні — повний вивід запуску (`.log`) і всі контейнери (`.csv`). Лист із ненульовим кодом виходу позначається як важливий.

Підмонтовані контейнери завжди пропускаються. Перевірки ті самі, що й у вікні. Усе пишеться в журнал із позначкою `[CLI]`. Повний довідник виводить `FSLTool.exe /?`.

Коди виходу: `0` — успішно, `1` — були помилки, `2` — неправильні параметри, `3` — критична помилка, `4` — скасовано, `5` — інший екземпляр уже працює, `6` — робота успішна, але звіт на email не надіслано (з іншими кодами помилка листа лише пишеться в журнал).

Приклад: щоночі о 01:00 стиснути все, що поверне щонайменше 2 GB, протягом не більше 4 годин:

```bat
schtasks /create /tn "FSLTool compact" /sc daily /st 01:00 /ru SYSTEM /rl HIGHEST ^
  /tr "\"C:\Tools\FSLTool.exe\" compact --min-gain 2 --max-minutes 240"
```

Щоденне сканування для історії:

```bat
schtasks /create /tn "FSLTool scan" /sc daily /st 06:00 /ru SYSTEM /rl HIGHEST /tr "\"C:\Tools\FSLTool.exe\" scan"
```

Те саме, з листом адміністраторам лише тоді, коли є проблеми:

```bat
schtasks /create /tn "FSLTool scan" /sc daily /st 06:00 /ru SYSTEM /rl HIGHEST ^
  /tr "\"C:\Tools\FSLTool.exe\" scan --mail-to admins@contoso.com --smtp smtp.contoso.local --mail-on problems"
```

- Завдання має виконуватися з найвищими правами (`/rl HIGHEST`).
- Під SYSTEM мережеві ресурси та AD доступні від імені облікового запису комп'ютера. Якщо профілі лежать на **іншому** сервері, використовуйте сервісний обліковий запис із правами адміністратора.
- У cmd запускайте через `start /wait FSLTool.exe …`, інакше командний рядок не чекатиме на завершення.

## Збірка та розгортання

```bash
dotnet publish src/FSLTool -c Release -o publish
```

Результат: один файл `publish\FSLTool.exe` (self-contained, x64, приблизно 62 МБ). Скопіюйте його на файловий сервер і запустіть: він сам запросить права адміністратора. Встановлювати .NET на сервері не потрібно.

Вимоги: Windows Server 2016+ / Windows 10+, права локального адміністратора на файловому сервері.

## Примітки

- Якщо шлях додано як `\\THISSERVER\share`, він переводиться в локальний через `Win32_Share`, щоб правильно визначити SMB-сесії. Для шляхів на **іншому** сервері визначається лише стан «Заблоковано», без імені хоста.
- Якщо том після підключення не з'являється, перевірте SAN policy (`diskpart` → `san`). За політики `OfflineAll` диски підключаються в стані Offline.
- «Сирота» означає, що SID не перекладається в обліковий запис (користувача видалено з AD). Якщо контролер домену недоступний, контейнер сиротою не позначається.
- «Вимкнений в AD» означає, що обліковий запис існує, але вимкнений або має прострочений термін дії. Такі контейнери можна видалити кнопкою «Видалити профіль» так само, як неактивні: кнопка з'являється, якщо обрано хоч один неактивний або вимкнений контейнер, і активна, лише якщо **всі** обрані відповідають одному з цих критеріїв і не підмонтовані. Перед видаленням контейнера, що змінювався нещодавно, стан облікового запису ще раз запитується в AD. Якщо AD не підтверджує, що запис вимкнений (зокрема коли контролер домену недоступний), контейнер пропускається. `lastLogonTimestamp` реплікується з затримкою до ~14 днів.
- Кольори тем — у `src/FSLTool/Themes/Palette.Light.xaml` і `Palette.Dark.xaml` (однаковий набір ключів), стилі елементів — у `Themes/Theme.xaml`; кольори використовуються лише через `DynamicResource`, інакше перемикання теми їх не змінить. Шрифт Manrope (`src/FSLTool/Assets/Fonts`) поширюється за SIL Open Font License 1.1 (`OFL.txt` поруч). Статичні файли згенеровано зі змінного `Manrope[wght].ttf` з репозиторію google/fonts (`fontTools.varLib.instancer` з `overlap=REMOVE`, хінтинг прибрано): WPF малює контури, що перекриваються, і автохінтинг Google Fonts з артефактами, тому файли, які віддає fonts.googleapis.com, не підходять.
- Рядки інтерфейсу лежать у `src/FSLTool/Localization/<область>.<мова>.json` і вбудовуються в exe. Нова мова додається парою файлів `<область>.<код>.json` для всіх областей (ключ `Lang.Native` — назва мови) і `Docs/Help.<код>.md`. Відсутній ключ показується англійською. Результати операцій, записи журналу й статуси, створені до перемикання мови, лишаються мовою, якою їх було створено; так само поля власного фільтра «Стан в AD (текст)», «Позначки (текст)» і «Результат останньої операції» порівнюються з текстом поточною мовою.
