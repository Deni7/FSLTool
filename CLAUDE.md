# FSLTool — правила проєкту

WPF-утиліта (.NET 10, `src/FSLTool`) для керування контейнерами FSLogix на файловому сервері. Інтерфейс, повідомлення, журнал і документація — українською.

## Документація — оновлювати разом із кодом

Будь-яка зміна функцій (нова дія, кнопка, колонка, картка, параметр, поріг, команда чи параметр режиму без вікна, файл даних, зміна поведінки чи обмежень безпеки) **в тій самій зміні** оновлює обидва джерела:

1. **Вбудовану довідку** — `src/FSLTool/Docs/Help.md`. Вона вбудовується в exe і показується у вікні «Довідка» (кнопка в лівій панелі, F1). Розділи `##` автоматично стають змістом. Підтримувана розмітка описана в коментарі на початку файлу (`MarkdownLite` рендерить лише її).
2. **Документацію проєкту** — `README.md` (таблиця «Можливості», розділи «Безпека», «Режим без вікна», «Примітки»).

Крім того:
- зміни команд і параметрів режиму без вікна дублюються в довідці консолі — `Headless.Help` у `src/FSLTool/Services/Headless.cs`;
- нові типові значення порогів — у таблиці «Пороги» в `Help.md`;
- видалена функція прибирається з усіх трьох місць.

Описуйте поведінку так, як вона реалізована (значення за замовчуванням, обмеження, що пропускається), а не як задумано.

## Збірка

```bash
dotnet build src/FSLTool
dotnet publish src/FSLTool -c Release -o publish
```

`publish/FSLTool.exe` — один self-contained exe (x64). Програма вимагає прав адміністратора (manifest), тому повний запуск і операції з дисками можна перевірити лише в підвищеному сеансі.

## Домовленості в коді

- Операції над контейнером — у `ProfileOperations` (блокувальні, з `OpReporter`), запускаються з UI через `MainViewModel.RunOnTargets`, у режимі без вікна — з `Headless`. Кожна операція починається з `EnsureFree`.
- Спільні дані в `%ProgramData%\FSLTool` пишуться через `Storage`/`ProfileStore` (перечитати → змінити → атомарно записати під міжпроцесним блокуванням).
- Кінці рядків: файли, що були з LF, лишаються LF; нові `.cs`/`.xaml` — CRLF.
